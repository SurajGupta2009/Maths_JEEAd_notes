# AGENTS.md — non-negotiable repo rules

You are editing a repo of hand-crafted **JEE Advanced + Olympiad math notes,
authored in Markdown**. The canonical content standard — module anatomy,
scope ladder, callout/question/numbering rules, correctness rules — lives in
[CONTRIBUTING.md](CONTRIBUTING.md); this file restates the
machine-checkable invariants and the exact commands. When the two disagree,
CONTRIBUTING.md wins for content and this file wins for commands.

## Structure (MUST)

```
notes/<Module-Slug>/        ★ canonical hand-authored Markdown — one folder per module
markdown is the medium; there is no HTML authoring step for new content
published/<Module-Slug>/    legacy standalone HTML mindmaps — FROZEN, verified
docs/                       ROADMAP, coverage checklist, formatting guide, diagrams
templates/                  markdown/ skeletons · html/ (legacy) · CHECKLIST.md
tools/                      verify-md.py, build-complete.py, convert_to_md.py,
                            build-mindmap.py, verify-math.py, verify-mindmap.py,
                            mindmap-overrides.json
```

- **One module = one folder under `notes/`** (kebab-case slug). No module
  files at the repo root; no module files outside `notes/` and `published/`.
- **One chapter = one folder named after the chapter**
  (`01-counting-basics/`), containing ALL of the chapter's content in its
  `README.md`. Exactly six chapter folders per module, numbered `01-`…`06-`.
- Module folder name = `NN-` + chapter title lowercased, non-alphanumerics
  collapsed to hyphens, `&` → `and`.
- Diagrams: `assets/fig-XX.svg` per module; referenced as
  `assets/fig-XX.svg` from module-level files, `../assets/fig-XX.svg` from
  inside chapter folders. Every image link must resolve.
- `notes/<Module>/00-WELL-ORDERED-THEORY.md` is hand-authored (one-page
  theory reference); all other module-level files are hand-authored too,
  EXCEPT the generated snapshot below.

## Generated artifacts (NEVER hand-edit)

- `notes/<Module>/<slug>-complete.md` — generated by
  `tools/build-complete.py` (module README → chapters → paper → solutions,
  with chapter asset links normalized back to `assets/`). Edit the chapter
  folders, then rebuild.
- `published/<Module>/<slug>-mindmap.html` — generated by
  `tools/build-mindmap.py` from (no longer maintained) source pages;
  source-less maps are safely left unchanged by the builder. Do not modify
  files under `published/` as part of content work.

## Math & content (MUST)

- Markdown math: inline `$…$`, display `$$…$$`. NEVER fake prose math with
  Unicode glyphs (`x² √ ≤ ≈ ℝ`); SVG diagram labels may use readable literal
  text.
- Callouts (fixed blockquote taxonomy): `⛁ First Principles` · `💡 Key Idea`
  · `⚠ Common Trap` · `★ Olympiad Extension` · `📌 Note` · `✔ Check` ·
  `➡ Bridge` · `🧮 Identity`.
- Questions: `#### **S1**[JEE Main][solved][technique]preview` (worked
  example) · `#### **P1**[JEE Adv][practice][concept]preview` (practice) ·
  `#### **Q1**[JEE Main][concept]preview` (paper, short `**Answer:**` line).
  Answers in `<details><summary>Answer + Reasoning</summary>` blocks (not in
  the paper). Solution = **method name first**, derivation, then a check.
- Numbering: `P1…Pn` and `S1…Sn` continuous per module, unique across all
  chapter folders, interleaved between theory sections; paper `Q1…Qn`
  continuous across lettered sections A–H, ≥30 (aim 38–40), difficulty
  ramping Main → Advanced → Olympiad; solutions repeat Q-ids verbatim.

## Correctness (MUST)

- Every paper answer is verified **numerically in pure Python (stdlib only —
  no numpy, no sympy)** BEFORE the solutions file is written. Unverified
  answer ⇒ reject your own work.
- Math delimiters must balance in every file (the gate enforces it).
- Before finishing, manually review every chapter folder for complete theory,
  every question/answer, rendering and every figure.

## Verify (MUST, before finishing)

```bash
python3 tools/verify-md.py                     # every notes/**/*.md — all PASS
python3 tools/build-complete.py all            # regenerate snapshots
git diff --exit-code -- 'notes/*-complete.md'  # snapshots stable
python3 tools/verify-math.py                   # every *.html — all PASS
python3 tools/verify-mindmap.py all            # published maps — all PASS
python3 tools/build-mindmap.py all             # source-less maps are safe no-ops
git diff --exit-code -- '*mindmap.html'        # published maps unchanged
```

Non-PASS output ⇒ fix the file; do not commit, do not loosen the verifier to
make content pass.

## Forbidden (NEVER)

- Never hand-edit generated snapshots or anything under `published/`.
- Never split a chapter's main text across multiple files, or store a
  chapter's content outside its folder.
- Never add dependencies, build systems, frameworks, caches or binary image
  files (SVG only) (maintainer opted out).
- Never rename module folders or retained map files; never place module files
  at the repo root.
- Never push to `main` or force-push; work on a branch and open a PR.
- Never commit answers that were not numerically verified.

## New module procedure

Follow `templates/CHECKLIST.md` (10 steps) while authoring a new module:
`notes/<Module-Slug>/` + `assets/` → module `README.md` from
`templates/markdown/module-index.md` → six chapter folders `01-…/README.md`
from `templates/markdown/chapter.md` → continuous P/S numbering →
`olympiad-paper.md` (≥30 Q, A–H, answer lines; **pure-Python verification
first**) → `olympiad-paper-solutions.md` → `00-WELL-ORDERED-THEORY.md` →
diagrams in `assets/` → `python3 tools/build-complete.py <Module>` → run all
gates → update README modules table and `notes/README.md` → PR.
